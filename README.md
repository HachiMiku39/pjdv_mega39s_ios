# PJDV M39 · Switch → iOS 移植研究

`pjdv_mega39s_ios` 记录《初音未来 Project DIVA MEGA39’s》Switch 版运行于 iPhone / iPad 的兼容层研究。App 名称为 **PJDV M39**。

目前已经能在 iPad 模拟器中进入原游戏标题、菜单和实时 3D 节奏游戏场景。**已修复纯蓝眼睛，以及《ACUTE》中角色 / 舞台倒置的问题；AudioRenderer 已接入真实 CoreAudio 输出。角色材质与光照仍在继续验证，完整音频听感与同步、触控体验和稳定真实 60 FPS 尚未验收。**

本仓库当前仅发布研究介绍和进展 README；游戏文件、密钥、提取资源、商业游戏可执行文件、着色器缓存与安装包均不包含在仓库中。

## 目标

- 支持 iPhone 和 iPad，横屏显示，按原始 16:9 比例适配。
- 还原 Switch 版实际的角色材质、舞台光照、反射和后处理。
- 保留原作谱面、歌曲时间轴、判定、HOLD、SLIDE 与计分行为。
- 支持原作触屏输入、可开关的虚拟手柄，以及 DualSense / Xbox 实体手柄；连接实体手柄后隐藏虚拟手柄。
- 以真实 60 FPS 和 1920×1080 输出为性能目标；正确渲染之后再评估 MetalFX。
- 先完成模拟器功能验证，再测试真机。

## 技术路线

CPU 采用原游戏 ARM64 程序适配路线，配合执行文件重写、模块载入和 Horizon 系统接口兼容。图形侧将实际 NVN 调用映射到 Metal，原始 Maxwell 着色器经 Ryujinx 翻译链转换为 SPIR-V / MSL。

Switch 与 Apple 设备都使用 ARM64，并不使二进制直接兼容；内存布局、系统服务、线程、输入、音频、图形与着色器语义仍需逐项实现和验证。

```text
Switch 游戏程序与资源
  ├─ ARM64 重写 / 模块载入 → Horizon 服务兼容 → 游戏逻辑
  ├─ NVN 命令 / 资源 / 状态 → Metal 后端
  ├─ Maxwell Shader → Ryujinx → SPIR-V → MSL
  ├─ AVC 视频 → VideoToolbox
  └─ 输入 / 音频 / 文件系统 → iOS 宿主接口
```

研究基线为 JP 版 v1.0.9（更新版本 589824），基础 Title ID `0100F3100DA46000`，包含 27 个 DLC。当前模拟器使用 Metal 3 路径；工程另有 Metal 4 真机路径，尚待真机验证。

## 已确认的渲染缺口：过滤拷贝未生成 mip

NVN 后端原先直接跳过不同尺寸的 Texture → Texture 拷贝。《愛言葉》的实际帧中，512×512 阴影纹理需要线性缩放写入 256×256、128×128 和 64×64 的 mip；旧实现使被采样的 mip 1 保持全黑。

已为实际观察到的 **Metal 3 / 2D / RGBA8_UNORM / 线性过滤**形态补充渲染式缩放，并限制读取与写入的 mip 视图，保留原始颜色与 alpha 语义。

验证结果：

- 修改后的模拟器 App 编译通过并进入实际歌曲场景。
- 第 19398 帧的 mip 0 → mip 1 / 2 / 3 拷贝均有执行记录。
- GPU 回读的 mip 1 不再全黑；与同帧 mip 0 的独立 CPU 双线性参考相比，RGB 最大误差 **0.5/255**、平均误差约 **0.0052/255**。
- 6 项独立 macOS GPU 检查通过，覆盖采样格式、sRGB、BGRA 顺序、双线性缩放和透明合成。

这证明了局部 mip 缺口的修复，**没有证明整体材质、颜色和光照已经正确**。该修复目前覆盖 Metal 3 的已观察形态，其他格式、拷贝形态和 Metal 4 仍需单独处理。

## 已验证的眼球修复：顶点输出默认 W

原版眼球顶点 shader 只写出模型坐标的 XY，片元 shader 在角膜 / 虹膜求交中还读取 W。现有离线翻译按阶段独立进行，没有调用 Ryujinx 的 `SetNextStage()`；消费阶段输入掩码为空，遗漏了用户输出分量的 `(0,0,0,1)` 初始化。MSL 的零初始化让模型 W 变成 0，导致原版 shader 走向纯蓝错误分支。

已在运行时源码编译入口补回默认值，并同步到着色器生成脚本。初始化发生在原版指令之前，显式写入的分量保留原行为；没有修改材质颜色或灯光常量。

- iOS 模拟器 App 构建通过并安装运行。
- 独立 Mac GPU 对照确认：缺失 W 从 0 恢复为 1，已写入的 XY 与另一输出的 W 保持原值。
- 636 份 vertex MSL 源码格式检查通过，含基础与模拟器变体；不等于 636 个独立原始 shader。
- 《愛言葉》实际实时 3D 场景恢复虹膜、瞳孔和高光；用户确认画面有所改善。
- 不切歌模式完整运行至结果页；尚未验收音频和节奏判定。
- 第 8417 帧捕获的环境 cubemap 六面均有有效 HDR 值，18 个浮点目标未发现 NaN / Inf；这不证明反射与灯光整体一致。

上述结论来自源码逻辑、GPU 对照和实际游戏画面三个层面。整体渲染与稳定真实 60 FPS 仍未验收。

## 已验证的后处理修复：屏幕四边形的 Y 方向

多人《ACUTE》原先出现角色 / 舞台持续倒置，谱面 UI 方向正常。实际 GPU 捕获确认，3D 中间纹理的方向正确，而最终 `magnify_linear` 屏幕四边形把它上下翻转。原版 NVN 的屏幕坐标约定与 Metal 的附件原点约定在这条路径中不一致。

已对从游戏 shader 清单确认的 48 个后处理 vertex-ID 四边形适配 clip Y，保留原版纹理坐标、采样区域和 RGBA 运算；运行时源码编译入口与生成脚本同步处理。修改范围不包含角色 / 舞台的 3D 投影、UI 网格和边缘清除几何。

- iOS 模拟器 App 构建通过并安装运行。
- 独立 Mac GPU 使用原版 `magnify_linear` 顶点 shader 复现上下翻转；修复后四象限测试图方向正确，每个 RGBA 分量误差不超过 1/255。
- 《ACUTE》多人实际游戏画面恢复正向，多镜头运行至结果页，未观察到闪退。
- 同一 App 内切换至《愛言葉》并完整运行至结果页；眼球细节保留，角色 / 舞台与谱面 UI 方向正常。两首歌曲均使用原游戏的不切歌模式，未修改谱面、判定或计分。
- 第 21381 帧的 31 份浮点渲染数据未发现 NaN / Inf；HDR 数据另行检查，未把直接转成 PNG 的截断值当成原始数值。

48 是适配清单中的 shader 数量，不代表 48 个 shader 都已在实际歌曲中单独完成视觉验收。更广的歌曲、透明效果、光照和反射仍需回归。

## 已接通的音频路径：AudioRenderer → CoreAudio

此前游戏主要使用的 AudioRenderer 仍是静音诊断服务，即使显示帧持续提交，也不会产生游戏声音。现在保留原版 SDK 的音轨配置、波形队列、输入序列化和完成状态读取，在服务边界将实际音轨混音为 48 kHz / 16-bit / 双声道 PCM，交给 CoreAudio RemoteIO 播放。iOS 宿主同时启用 AVAudioSession 播放会话。

完成计数根据系统实际消耗输出缓冲更新；不再用静音计时器伪造完成事件。提前队列限制为 4 × 240 样本（20 ms），这是软件队列上限，不能当作测得的端到端延迟。

已修复原版缓存刷新指令在 iOS 的执行兼容，以及音轨停止后丢弃预加载缓冲、环形队列位置未前进导致歌曲断流的问题。

- iOS 模拟器构建通过并安装运行。
- PCM 声道顺序、暂停 / 恢复、完成计数、循环、采样率转换、增益、DSP-ADPCM 已知有符号样本，以及停止时预加载 / 重新开始的独立测试通过 AddressSanitizer / UndefinedBehaviorSanitizer 检查。
- 系统已消耗的实际音频缓冲捕获为 48 kHz 立体声，样本含有效非零信号；这与仅提交音频数据不同，但尚未替代扬声器听感验收。
- 《愛言葉》在不切歌模式完整运行到结果页，音乐缓冲持续消耗；暂停期间样本计数保持，恢复后继续增长，未观察到闪退。
- 同一 App 返回选曲后进入《ACUTE》，音乐缓冲再次持续消耗；本次先验证了换曲启动，尚未把《ACUTE》全曲音频记为验收完成。

当前验证范围是本作观察到的无独立 DSP 音效链、直接立体声输出配置。完整滤波器 / 子混音、ADPCM 上下文和循环语义、音画及判定同步、更多歌曲和真机仍需单独验证。没有修改谱面、判定、计分或原作音量常量。

协议字段参考 [libnx 的 AudioRenderer 定义](https://switchbrew.github.io/libnx/audren_8h_source.html)，播放会话参考 [Apple AVAudioSession playback 文档](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/playback)，并以实际 SDK 输入 / 输出确认本作所用版本。

## 材质与光照的排查方向

当前执行的是翻译后的原版游戏着色器。实际绑定对应 `cloth_npr1`、`hair_npr1`、`skin_npr1` 和 `glass_eye`；服装法线贴图已绑定并启用。已观察到浮点 3D 中间目标、曝光、色调映射、FXAA 和 UI 合成过程；仍需核对这些计算的实际结果。

当前仍缺少同版本、同模组、同镜头的严格原版画面对照，局部缺口修复不能视为整体材质和光照已完全还原。

下一步对照原游戏绑定和社区研究，逐项核对：

1. CLOTH / HAIR / SKIN / EYEBALL 等材质变体与实际 shader 的对应关系。
2. Diffuse、Normal、Specular、Environment Cube 的格式、纹理视图、mip、采样器与绑定槽。
3. 法线 / 切线变换、灯光常量、各向异性高光与眼睛采样。
4. cubemap 六面、浮点 HDR 中间值、运算顺序和 Tone Mapping。
5. 同歌曲、同服装、同镜头的对照与回归。

CPU 纹理转储和延后 GPU 池回读仍为零，不能作为原始资源上传一致性的证据。GPU 实际纹理与 cubemap 六面、原始浮点目标已有有效导出；原始压缩资源到 GPU 纹理的逐字节一致性尚未证明。

修复以 Switch 版实际效果为基线，不通过全局饱和度、曝光或反光滤镜掩盖问题，也不直接套用 Future Tone 的渲染参数。
