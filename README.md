# PJDV M39 · Switch → iPadOS / macOS 移植研究

`pjdv_mega39s_ios` 记录《初音未来 Project DIVA MEGA39’s》Switch 版运行于 iPadOS / macOS 的兼容层研究。当前暂不支持 iPhone。App 名称为 **PJDV M39**。

目前已经能在 iPad 模拟器中进入原游戏标题、菜单和实时 3D 节奏游戏场景；M4 iPad 真机已安装运行，M3 Max Mac Catalyst 版也已进入原游戏。MetalFX Spatial 已接入；M4 真机的《ゴーストルール》困难 / 不切歌模式已完整运行三轮，正常演奏采样约 60 FPS，仍有少量长间隔和载入停顿，尚不代表全部歌曲通过。**已修复纯蓝眼睛，以及《ACUTE》中角色 / 舞台倒置的问题；AudioRenderer 已接入真实 CoreAudio 输出。角色材质与光照仍在继续验证，完整音频听感与同步、触控体验和稳定真实 60 FPS 尚未验收。**

本仓库当前仅发布研究介绍和进展 README；游戏文件、密钥、提取资源、商业游戏可执行文件、着色器缓存与安装包均不包含在仓库中。

## 目标

- 当前支持范围为 iPadOS / macOS（Mac Catalyst），暂不支持 iPhone；横屏显示，按原始 16:9 比例适配。
- 启动时要求 Apple GPU family 9 或更新，最低按 M3 / A17 级别；采用实际 GPU 能力检测。
- 还原 Switch 版实际的角色材质、舞台光照、反射和后处理。
- 保留原作谱面、歌曲时间轴、判定、HOLD、SLIDE 与计分行为。
- 支持原作触屏输入、可开关的虚拟手柄，以及 DualSense / Xbox 实体手柄；连接实体手柄后隐藏虚拟手柄。
- 以真实 60 FPS 和 1920×1080 输出为性能目标；已加入 MetalFX Spatial 与普通放大对照，持续验证画质和帧时间。
- 光追为后续实验方向，当前没有接入游戏阴影 / 反射光追，默认渲染沿用原版材质与光照。
- 并行保留模拟器功能回归与 M4 iPad 真机验证，分别记录测试结果。

## 技术路线

CPU 采用原游戏 ARM64 程序适配路线，配合执行文件重写、模块载入和 Horizon 系统接口兼容。图形侧将实际 NVN 调用映射到 Metal，原始 Maxwell 着色器经 Ryujinx 翻译链转换为 SPIR-V / MSL。

Switch 与 Apple 设备都使用 ARM64，并不使二进制直接兼容；内存布局、系统服务、线程、输入、音频、图形与着色器语义仍需逐项实现和验证。

```text
Switch 游戏程序与资源
  ├─ ARM64 重写 / 模块载入 → Horizon 服务兼容 → 游戏逻辑
  ├─ NVN 命令 / 资源 / 状态 → Metal 后端
  ├─ Maxwell Shader → Ryujinx → SPIR-V → MSL
  ├─ AVC 视频 → VideoToolbox
  └─ 输入 / 音频 / 文件系统 → iOS 宿主接口
```

研究基线为 JP 版 v1.0.9（更新版本 589824），基础 Title ID `0100F3100DA46000`，包含 27 个 DLC。当前模拟器使用 Metal 3 路径；Metal 4 真机路径已在 M4 iPad 启动运行；仍需完整歌曲、材质和输入回归。

## MetalFX 与真机启动验证

MetalFX Spatial 已接到原游戏最终色调映射后的画面，采用 perceptual 模式，将 1280×720 输出重建到 1920×1080。没有插帧，也没有改变谱面、歌曲时间轴或输入更新频率。Scaler 和输入 / 输出纹理由三个在途槽复用，按实际输出尺寸更新；不支持时明确回退到普通放大。

当前 iOS 模拟器 SDK 不提供 MetalFX，界面会禁用超分选项。M4 iPad 真机与 M3 Max Mac 上已观察到实际 MetalFX 编码和输出。原游戏已在源画面内合成谱面，因此这一版会处理整个游戏帧，尚未实现音符 / UI 在超分后单独以 1080p 绘制。

M4 iPad 已修复启动时地址空间预留失败：本作主模块有约 3 GB 的静态 BSS 映射，沿用参考工程额外预留 5 GB 的方案会在该设备启动阶段失败。按本作实际映像占用与原有应用内存池计算，动态堆预算约 205 MiB；将兼容层预留缩到 1.5 GiB，保留 512 MiB 的动态堆容量、原别名 / 栈分区及原应用内存预算。没有新增扩展虚拟寻址 entitlement。

真机菜单的一个连续采样窗口中，300 帧实际上屏无掉帧，p99 间隔 16.67 ms，游戏绘制 GPU 中位约 5.3 ms。**这只证明所测菜单场景，不能推定所有实时 3D 歌曲稳定 60 FPS。** 超分增加了画面重建步骤；当前未降低原 3D 内部渲染分辨率，因此不能把它宣称为已经提升游戏速度。

虚拟手柄已补齐并采用 Switch 布局：双摇杆、L3 / R3、方向键、X / Y / A / B、L / R、ZL / ZR、＋ / －。实体手柄连接自动隐藏和触屏穿透继续保留。图标改为用户提供图片的严格 1:1 裁切，没有使用生成的重绘版本。

## 片头 MV 与原版渲染研究

原资源中的 `MEGA39sOP.mp4` 为约 93.14 秒、1280×720、60 FPS 的 H.264 High 视频，包含 5584 帧，使用 BT.709 限幅 YUV420。`SEGAlogo_Attack_White_Ver.4.mp4` 也属于预录视频。它们画面中的 3D 外观不能作为运行时实际绘制人物网格的证据。

已对 MV 全部 5584 帧进行亮度 / 色度变化统计和解码帧哈希检查，并人工查看全片取样图及第 1440–1471 帧的连续角色近景。该段能观察到随姿态变化的发丝高光、虹膜 / 角膜层次、皮肤柔和阴影、衣料亮暗分区和背景合成。只有 3 对相邻解码图像完全相同；这不是移植版本运行帧率的测试。

当前视频链路是 H.264 → VideoToolbox → 原版 OMX 缓冲与 PTS 排序 → 原版客户端 NV12 布局 → `sprite_pct_movie` → 游戏输出 → Metal / 可选 MetalFX。原版 movie fragment shader 只采样亮度与色度两个 2D 纹理，以原常量缓冲中的系数执行 YUV→RGB，并乘顶点颜色。逐帧对照将分别核对布局、色域 / 范围、时间戳、纹理上传和最终合成。

实时 3D 使用另一组原版材质：已检查 `hair_npr1`、`skin_npr1`、`glass_eye`、`cloth_aniso` 和 `tonemap_npr1` 的翻译源码，存在多张 2D 纹理、环境 cubemap 和多个材质 / 灯光常量缓冲。**画面细节不足不能直接归因于模型面数，必须核对法线 / 切线、原版高光、环境采样、阴影与色调映射。** 文件存在也不证明某个变体在某一帧被实际使用；下一步以实时 3D 捕获的实际绑定及中间目标验证。

预录 MV 作为视觉参考，不能反推出精确灯光参数或证明光追效果。正在研究可选光追的接入位置；游戏中的光追阶段尚未实现，原版渲染仍是验收基线。

## 已确认的渲染缺口：过滤拷贝未生成 mip

NVN 后端原先直接跳过不同尺寸的 Texture → Texture 拷贝。《愛言葉》的实际帧中，512×512 阴影纹理需要线性缩放写入 256×256、128×128 和 64×64 的 mip；旧实现使被采样的 mip 1 保持全黑。

已为实际观察到的 **Metal 3 / 2D / RGBA8_UNORM / 线性过滤**形态补充渲染式缩放，并限制读取与写入的 mip 视图，保留原始颜色与 alpha 语义。

验证结果：

- 修改后的模拟器 App 编译通过并进入实际歌曲场景。
- 第 19398 帧的 mip 0 → mip 1 / 2 / 3 拷贝均有执行记录。
- GPU 回读的 mip 1 不再全黑；与同帧 mip 0 的独立 CPU 双线性参考相比，RGB 最大误差 **0.5/255**、平均误差约 **0.0052/255**。
- 6 项独立 macOS GPU 检查通过，覆盖采样格式、sRGB、BGRA 顺序、双线性缩放和透明合成。

这证明了局部 mip 缺口的修复，**没有证明整体材质、颜色和光照已经正确**。后续已补充同一 RGBA8 2D 形态的 Metal 4 实现，验证范围见下文；其他格式与拷贝形态仍需单独处理。

## 已验证的眼球修复：顶点输出默认 W

原版眼球顶点 shader 只写出模型坐标的 XY，片元 shader 在角膜 / 虹膜求交中还读取 W。现有离线翻译按阶段独立进行，没有调用 Ryujinx 的 `SetNextStage()`；消费阶段输入掩码为空，遗漏了用户输出分量的 `(0,0,0,1)` 初始化。MSL 的零初始化让模型 W 变成 0，导致原版 shader 走向纯蓝错误分支。

已在运行时源码编译入口补回默认值，并同步到着色器生成脚本。初始化发生在原版指令之前，显式写入的分量保留原行为；没有修改材质颜色或灯光常量。

- iOS 模拟器 App 构建通过并安装运行。
- 独立 Mac GPU 对照确认：缺失 W 从 0 恢复为 1，已写入的 XY 与另一输出的 W 保持原值。
- 636 份 vertex MSL 源码格式检查通过，含基础与模拟器变体；不等于 636 个独立原始 shader。
- 《愛言葉》实际实时 3D 场景恢复虹膜、瞳孔和高光；用户确认画面有所改善。
- 不切歌模式完整运行至结果页；尚未验收音频和节奏判定。
- 第 8417 帧捕获的环境 cubemap 六面均有有效 HDR 值，18 个浮点目标未发现 NaN / Inf；这不证明反射与灯光整体一致。

上述结论来自源码逻辑、GPU 对照和实际游戏画面三个层面。整体渲染与稳定真实 60 FPS 仍未验收。

## 已验证的后处理修复：屏幕四边形的 Y 方向

多人《ACUTE》原先出现角色 / 舞台持续倒置，谱面 UI 方向正常。实际 GPU 捕获确认，3D 中间纹理的方向正确，而最终 `magnify_linear` 屏幕四边形把它上下翻转。原版 NVN 的屏幕坐标约定与 Metal 的附件原点约定在这条路径中不一致。

已对从游戏 shader 清单确认的 48 个后处理 vertex-ID 四边形适配 clip Y，保留原版纹理坐标、采样区域和 RGBA 运算；运行时源码编译入口与生成脚本同步处理。修改范围不包含角色 / 舞台的 3D 投影、UI 网格和边缘清除几何。

- iOS 模拟器 App 构建通过并安装运行。
- 独立 Mac GPU 使用原版 `magnify_linear` 顶点 shader 复现上下翻转；修复后四象限测试图方向正确，每个 RGBA 分量误差不超过 1/255。
- 《ACUTE》多人实际游戏画面恢复正向，多镜头运行至结果页，未观察到闪退。
- 同一 App 内切换至《愛言葉》并完整运行至结果页；眼球细节保留，角色 / 舞台与谱面 UI 方向正常。两首歌曲均使用原游戏的不切歌模式，未修改谱面、判定或计分。
- 第 21381 帧的 31 份浮点渲染数据未发现 NaN / Inf；HDR 数据另行检查，未把直接转成 PNG 的截断值当成原始数值。

48 是适配清单中的 shader 数量，不代表 48 个 shader 都已在实际歌曲中单独完成视觉验收。更广的歌曲、透明效果、光照和反射仍需回归。

## 已验证的阴影修复：图像过滤链的 Y 方向

实际捕获中，人物阴影输入轮廓正向，经过 `imgfilter/copy`、`box4` 等过滤后，512×512 遮罩上下倒置。此前的后处理修复只覆盖 vertex-ID 四边形，遗漏了用顶点属性提供归一化 XY 的图像过滤四边形。

已为实际使用的六个原版过滤 vertex shader 补充 clip Y 转换：`esm_gauss_s`、`esm_gauss_t`、`esm_filter_min`、`esm_filter_erosion`、`copy`、`box4`。运行时入口和生成脚本均已同步，保留原版 UV、采样偏移、过滤计算、颜色、灯光和材质参数。3D 模型投影与 UI 几何不属于这项修改的范围。

- 六项独立 macOS Metal GPU 对照均复现旧代码翻转，修复后保留全部 RGBA 通道和方向。
- iOS 模拟器构建通过并安装，进入《愛言葉》实际 3D 歌曲场景。
- 第 8190 帧的 1024×1024 输入轮廓与 512×512 输出遮罩方向一致；与同帧输入缩小后的轮廓重合度（IoU）为 **0.9774**，与上下翻转参考仅为 **0.0266**。这是过滤链方向检查，不能视为与 Switch 原版完整画面一致的指标。
- 同帧捕获的 23 份浮点渲染数据未发现 NaN / Inf；新版《愛言葉》在不切歌模式完整运行至结果页，未观察到闪退。

整体材质、高光、反射与同版本 Switch 的同镜头对照仍待完成。深度范围也在核查，尚未依据未确认的默认值修改投影。

## 已接通的音频路径：AudioRenderer → CoreAudio

此前游戏主要使用的 AudioRenderer 仍是静音诊断服务，即使显示帧持续提交，也不会产生游戏声音。现在保留原版 SDK 的音轨配置、波形队列、输入序列化和完成状态读取，在服务边界将实际音轨混音为 48 kHz / 16-bit / 双声道 PCM，交给 CoreAudio RemoteIO 播放。iOS 宿主同时启用 AVAudioSession 播放会话。

完成计数根据系统实际消耗输出缓冲更新；不再用静音计时器伪造完成事件。提前队列限制为 4 × 240 样本（20 ms），这是软件队列上限，不能当作测得的端到端延迟。

已修复原版缓存刷新指令在 iOS 的执行兼容，以及音轨停止后丢弃预加载缓冲、环形队列位置未前进导致歌曲断流的问题。

- iOS 模拟器构建通过并安装运行。
- PCM 声道顺序、暂停 / 恢复、完成计数、循环、采样率转换、增益、DSP-ADPCM 已知有符号样本，以及停止时预加载 / 重新开始的独立测试通过 AddressSanitizer / UndefinedBehaviorSanitizer 检查。
- 系统已消耗的实际音频缓冲捕获为 48 kHz 立体声，样本含有效非零信号；这与仅提交音频数据不同，但尚未替代扬声器听感验收。
- 用户已确认片头和菜单声音正常；歌曲音画与判定同步仍需单独检查。
- 《愛言葉》在不切歌模式完整运行到结果页，音乐缓冲持续消耗；暂停期间样本计数保持，恢复后继续增长，未观察到闪退。
- 同一 App 返回选曲后进入《ACUTE》，音乐缓冲再次持续消耗；本次先验证了换曲启动，尚未把《ACUTE》全曲音频记为验收完成。

当前验证范围是本作观察到的无独立 DSP 音效链、直接立体声输出配置。完整滤波器 / 子混音、ADPCM 上下文和循环语义、音画及判定同步、更多歌曲和真机仍需单独验证。没有修改谱面、判定、计分或原作音量常量。

协议字段参考 [libnx 的 AudioRenderer 定义](https://switchbrew.github.io/libnx/audren_8h_source.html)，播放会话参考 [Apple AVAudioSession playback 文档](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/playback)，并以实际 SDK 输入 / 输出确认本作所用版本。

## 材质与光照的排查方向

当前执行的是翻译后的原版游戏着色器。实际绑定对应 `cloth_npr1`、`hair_npr1`、`skin_npr1` 和 `glass_eye`；服装法线贴图已绑定并启用。已观察到浮点 3D 中间目标、曝光、色调映射、FXAA 和 UI 合成过程；仍需核对这些计算的实际结果。

当前仍缺少同版本、同模组、同镜头的严格原版画面对照，局部缺口修复不能视为整体材质和光照已完全还原。

下一步对照原游戏绑定和社区研究，逐项核对：

1. CLOTH / HAIR / SKIN / EYEBALL 等材质变体与实际 shader 的对应关系。
2. Diffuse、Normal、Specular、Environment Cube 的格式、纹理视图、mip、采样器与绑定槽。
3. 法线 / 切线变换、灯光常量、各向异性高光与眼睛采样。
4. cubemap 六面、浮点 HDR 中间值、运算顺序和 Tone Mapping。
5. 同歌曲、同服装、同镜头的对照与回归。

CPU 纹理转储和延后 GPU 池回读仍为零，不能作为原始资源上传一致性的证据。GPU 实际纹理与 cubemap 六面、原始浮点目标已有有效导出；原始压缩资源到 GPU 纹理的逐字节一致性尚未证明。

修复以 Switch 版实际效果为基线，不通过全局饱和度、曝光或反光滤镜掩盖问题，也不直接套用 Future Tone 的渲染参数。

Luma 的 SSS 模块跟踪几何准备、NPR 边缘、降采样、SSS 准备和最终合成；聚光灯模块跟踪深度准备、独立光照合成及 Tonemap 使用。这里参考阶段和资源依赖，不直接套用 PC 的 shader 哈希、槽位或地址。配套 [Megamix-FT_Restoration](https://github.com/lsmsmx/Megamix-FT_Restoration) 明示顶点重编译因 UAM 位运算问题默认移除，也不能视为完整 shader 还原。

## Metal 4 阴影 mip 拷贝补齐

M4 真机旧日志仍报告 `512×512 → 256×256, flags 0x1, RGBA8` 拷贝被跳过：此前修复只编译进 Metal 3。已为 Metal 4 增加同样的单 mip 视图、线性缩放、区域边界处理；每次拷贝使用独立不可变参数与 argument table，资源保留至 GPU 完成，并声明跨编码器依赖。

直接提取运行时实际 helper，在 M3 Max GPU 分别测试 Metal 3 / Metal 4：同一纹理的 256 / 128 / 64 阴影 mip、局部缩小、局部放大均通过，RGBA 与独立 CPU 双线性参考最大误差约 **1.073/255**。同一提交编码五次不同拷贝；另有五种越界 / 不支持形态正确拒绝。iPad 与 Mac Catalyst Release 构建通过。以上属于局部 GPU 验证，尚不表示原版完整光照或稳定 60 FPS 已通过。

M4 iPad 的《ACUTE》不切歌场景已实际运行并完成单帧捕获。第 19006 帧中，两组 512×512 阴影纹理（serial 486 / 487）的 256 / 128 / 64 mip 均不再为全黑；六组 RGBA 回读与各自 mip 0 的独立 CPU 双线性参考最大误差均为 **0.5/255**。本帧仍使用 `nonsss` 材质，执行降采样、曝光、Gaussian / Cone 过滤、Tonemap、FXAA 等阶段，未观察到 SSS 后处理。捕获得到 46 个颜色目标。观察窗口的显示计数约 60 FPS；这不证明每个 PV 动画帧均独立更新，也不是全部歌曲稳定 60 FPS 验收。

## 可选光线追踪的接入设计

游戏阴影 / 反射的光追合成尚未实现；独立 BLAS / TLAS、refit 和真实静态舞台的离屏射线对照已通过。运行时需要同时检查 Apple GPU family 9 与 `supportsRaytracing`；Apple 明确将硬件光追加速引入 M3 / A17 Pro 的 Apple9 GPU。[Apple GPU 说明](https://developer.apple.com/videos/play/tech-talks/111375/)

优先顺序是 **单灯舞台阴影 → 角色自阴影 → 指定舞台表面的单次反射**。保留原版 Toon 材质及环境光，光追只替换对应的可见性 / 反射输入，避免重复乘阴影或叠加同一束光。第一阶段先验证固定场景的遮挡，再加入动画；不先做全局路径追踪。

所需桥接数据包括实际绘制的顶点与索引、实例变换、骨骼 / 变形后的几何、相机、灯光及材质分类。已为经过原始 shader 核对的 `stage_blinn_nonsss` 静态不透明舞台建立单帧世界空间网格导出；其他材质、角色和透明物体尚未建立完整场景桥。静态舞台可缓存 BLAS；动态角色需要经核对的 GPU 蒙皮结果，更新 BLAS，并更新实例 TLAS。拓扑变化要重建，不能仅 refit。[Apple 场景构建与 refit 指南](https://developer.apple.com/videos/play/wwdc2023/10128/)

第一版计划半分辨率阴影遮罩，使用原灯光投射射线，分别输出角色自阴影和地面投影遮罩。发丝 / 透明裁切按原 UV 和 alpha 拒绝交点；缺少该步骤会出现实心发片阴影。结合深度、法线及经过验证的运动数据做降噪；镜头切换重置历史。去噪结果接入对应光照阶段，再走原版 SSS / 后处理 / Tonemap，谱面 UI 保持独立。

光追作为可选增强，默认关闭并保留原阴影回退。60 FPS 总预算为每帧 16.67 ms；加速结构更新、射线、降噪和合成都必须纳入实测，不能以支持硬件光追推定可达到目标帧率。预录片头 MV 不参与实时光追。

## RT 的实际 GPU 与舞台网格验证

新增显式开启的诊断入口，正常运行不分配光追加速结构或执行射线测试。代码使用 Metal 4 的地址式几何描述、间接实例、明确驻留、跨编码器依赖和 GPU 完成后资源复用；Metal 3 路径也有独立验证。

- M3 Max（Metal 3 / Metal 4）与 M4 iPad（Metal 4）：BLAS / TLAS 初建、实例移动 refit、网格变形 refit、遮挡掩码和最大距离拒绝共六项测试通过。每项测试 65,536 条射线，以独立 CPU 三角形相交算法核对命中、距离和重心坐标。这部分使用合成三角形。
- 用户指定的压力歌曲为 **《ゴーストルール》**，原曲目 `pv_266`。M4 真机第 15071 帧导出 16 组经过 shader 核对的静态不透明舞台网格，共 **29,047 个三角形**；顶点与索引仍来自实际游戏绘制，世界坐标遵循原顶点 shader 常量矩阵。
- 同一舞台子集在 M3 Max 和 M4 iPad 上执行 256×256 离屏射线测试。两台 GPU 的 65,536 条命中 / 距离结果一致；1,024 条独立 CPU 抽样全部通过，603 条命中，最大距离误差约 **2.3×10⁻⁶ 个世界坐标单位**。
- M4 本次诊断的初建加射线 GPU 时间约 **7.54 ms**，建树后单次射线工作约 **0.077 ms**。这是有限舞台子集、固定方向、无材质采样的离屏工作量，不能推定完整游戏光追的速度或 60 FPS。

这些结果证明静态舞台几何可以进入硬件光追管线。**角色蒙皮、发丝 alpha、原灯光对应射线、阴影 / 反射输入、降噪和游戏最终合成尚未接入**，所以当前游戏画面不能称作“已开启 RT”。原版光照仍是画质基线。
