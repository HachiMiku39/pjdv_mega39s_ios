## 0.1.5 更新与验证范围

- **降低安装门槛**：iOS／iPadOS 最低 17.0，最低 GPU 为 Apple family 7（A14／M1 同代），iPhone 同样开放。iOS 使用标准 Metal 命令队列兼容提交路径；build10 的 Mac 最低目标已降为 M1／macOS Big Sur 11，实际旧系统验收尚未完成。
- **原生触屏与按键布局（build15／16）**：快速重按不再合并成旧触点；跨线程快照按修订号发布。全部 18 个虚拟控件可分别移动和缩放，肩键保持长宽比，按设备布局分别保存。原生 Touch Play 测试时请关闭虚拟手柄，避免其实际按键区域截获触点。
- **低配档（family 7／8）**：首次默认 720p、标准画质，最高输出 1080p；禁用 HDR、光追和 60→120。MetalFX Spatial 根据实际设备能力提供。低配的分辨率与画质单独保存，旧高配设置不能绕过输出限制。
- **30→60 模拟器实验**：iPhone 18 Pro／iOS 27.2 的独立合成场景通过中间帧读回、开关对照、切镜头、暂停恢复及重新进入检查。模拟器没有 MetalFX 框架，采用明确标注的替代算法；这不是实际游戏或苹果 MetalFX 插帧验收。独立插帧实验需要 iOS 26。真实游戏插帧研究链从 build9 起接入，但画质未通过验收，build10 普通启动同样不开放。

**本版为兼容性预览：** iOS、模拟器和 macOS 构建通过，family 7 限制档在 iPhone 18 Pro 模拟器可显示片头、标题和主菜单，720p／1080p 输出正常。**尚未在 iOS 17、M1／A14 真机验收**，也未验证 4 GB 内存设备的稳定性、全曲帧率和高配设备改走 Metal 3 后的 HDR／RT 回归。模拟器约 60 FPS 的菜单数据不代表旧设备性能。

## 本轮改进

- **场景与景深**：修复两条片元着色器的透明度控制流，以及 NVN 到 Metal 的深度范围转换。在已抽查的《39みゅーじっく！》镜头中恢复立方体表面、发光圆环、大屏内容和人物对焦；这不代表所有歌曲或光照已完全还原。
- **载入**：本体和 27 DLC 共用原生 FARC/gzip 解压路径；477,748 个压缩条目的内容核验通过。收益取决于歌曲资源组成，仍不能保证所有歌曲都瞬间载入。
- **独立渲染依赖**：精简包内附匹配的 Metal 着色器与反射缓存，资源导入后不依赖开发机的缓存目录。
- **iPhone 实验适配**：开放满足 Apple GPU family 7 的 A14 同代及更新设备（兼容性预览）；最高 1080p、60 FPS，隐藏 1440p、屏幕分辨率输出和 120 FPS 选项。手机布局与折叠姿态先在模拟器验证。
- **折叠布局**：展开居中显示，合上横屏，半折分为上部游戏和下部控制区；保留原比例，利用自然黑边放系统状态栏。折叠模拟器适配不等同于真实折叠设备验收。
- **全部虚拟控件编辑**：进入游戏前，在启动首页的“虚拟按键：大小与位置”（build16 及更早版本称“虚拟手柄布局”）中，分别调整全部 18 个按键／摇杆的大小与位置，按手机、平板及折叠姿态保存。折叠设备默认摇杆缩小。
- **语言对应**：选择日文、简体中文或繁体中文时，宿主界面与游戏使用同一语言。真机发现英文字符串表并不等于完整英文菜单：这份 JP 包会混用日文图片，因此暂不开放英文、韩文选项；旧设置选到这些语言时统一回退日文。少数底层诊断仍保留技术文本。
- **手柄图标**：新增按实体手柄类型选择游戏图标的路径，Xbox 的旋律预览顺序为 **Y、X、A、B（上、左、下、右）**；PS 复用原有符号素材，保留箭头模式和既有输入映射。M4 iPad 已用诊断指定 Xbox 图标验证主菜单/设置底栏、YXAB 预览和按键设定；本轮未连接 Xbox 实体手柄，热插拔识别与完整谱面仍待更多实测。部分预烘焙帮助图、标题 Press A 和中央手柄示意图仍显示原版标识。

## iPad 安装与首次启动

1. 给 IPA 使用你自己的有效开发签名，安装到受该签名允许的 iPad / iPhone。公开 IPA 未签名，不能靠把文件拷到 iPad 就完成安装。
2. 按系统要求启用 [开发者模式](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)。如系统要求信任开发签名，在“设置 → 通用 → VPN 与设备管理”处理对应开发者。
3. 打开 PJDV M39，使用下面的 XCI 导入或已提取资源方式。资源未就绪时“启动游戏”不可用。
4. 点击“启动游戏”，用虚拟 A、键盘 D 或实体手柄的确认键进入。A 可以跳过开头视频。

本地 development IPA 的签名只覆盖当前登记设备，并有有效期；换 iPad 需要重签。更新测试版尽量覆盖安装，先备份存档再做卸载操作。

**版本提示：** build14 已包含根目录自动导入、备用文件夹入口和导入内存修复；历史 build10 不含这些新入口。

### 方式一：根目录自动导入（build13 起，推荐）

1. 安装后至少打开一次 App，再进入“文件”App →“我的 iPad／iPhone”→ **PJDVM39**（系统也可能显示 **PJDV M39**）。这是 App 暴露的 Documents 根目录。
2. 把已解压的 **MEGA39’s `.xci`** 和自己的 **`prod.keys`** 拷到这个根目录，同级放置：

   ```text
   PJDVM39/
   ├── MEGA39s.xci       # 文件名可不同，扩展名为 .xci
   ├── prod.keys
   └── GameResources/   # 导入后由 App 生成
   ```

3. 等“文件”App／访达的复制完成，回到 PJDV 的**启动首页**，保持 App 在前台。App 每两秒检查根目录；文件大小和修改时间稳定至少四秒后，会自动打开资源管理，校验密钥并开始 XCI 预检、提取。
4. 等界面显示“导入完成”，点“完成 → 启动游戏”。只放入密钥时会先保存密钥；已有有效本机密钥时，之后只放入 XCI 也可导入。

也可以通过 Mac 访达 → iPad／iPhone →“文件”→ PJDV M39，把这两个文件拷入同一个 App 根目录。目录中的 XCI 文件名可以不同，包内容仍须为支持的 MEGA39’s Title ID（0100F3100DA46000）。

- 只检测根目录中的普通 `.xci`／`.keys` 文件；放在 `GameResources` 或其他子文件夹中的源文件不会触发自动导入。
- 多份 XCI 或密钥会显示 App 内列表，由你选择。ZIP／7z 需先解压，云端文件需先下载完整。
- 四秒稳定只是开始检查的条件。若大型文件仍在复制，截断或校验失败会停止；复制完成后可在资源管理点 **“检测 App 根目录中的 XCI／密钥”** 重试。
- 同一批成功导入的文件下次启动不会重复导入。游戏运行期间不扫描，也不后台导入。

### 方式二：手动选择 XCI（支持外置盘）

1. 在首页打开“导入 XCI／资源管理”。首次先点 **“选择／更换 prod.keys”**，选择自己的密钥；已保存有效密钥时可跳过。
2. 点 **“导入 XCI”**，选择 MEGA39’s `.xci`。源文件可以留在外置盘。
3. 保持 App 在前台，等待基础资源、所选更新合并及包内实际 DLC 导入完成，再点“完成 → 启动游戏”。使用外置盘时，在整个导入期间保持连接。

### 方式三：文件点不动时，从所在文件夹选择（build13 起）

这适用于系统文件列表能浏览、但点击 XCI／密钥没有反应的情况：

1. 打开资源管理，点 **“备用：从文件夹选择密钥”**。
2. 在系统窗口进入密钥所在的文件夹，点右上角 **“打开”**；随后在 **App 自己的文件列表**中点选 `.keys`。
3. 再点 **“备用：从文件夹选择 XCI”**，同样打开 XCI 所在文件夹，再从 App 列表中点选 `.xci`。

这个入口先授权文件所在的目录，再直接读取选中的源文件。M1／iPadOS 18 用户可优先回测根目录自动导入或这个备用入口；该设备上的新版效果仍待确认。

### 导入进度、空间与重试

build13 起，预检显示当前阶段和活动指示；识别出资源总量后显示**百分比、已完成／总大小**。每 0.5 秒刷新**读取速度、写入速度、累计读写量和耗时**。读取包含 XCI 和已有资源校验，写入统计成功写出的资源数据；续导时通过校验的已有文件不会虚增写入。速率包含缓存影响，表示应用层传输速度。

原 XCI 保留在所选位置，不移动，也不先复制整份源文件；根目录密钥也会保留。提取出的资源另写入 `GameResources`，占用额外空间。已测 v1.0.9＋27 DLC 的资源约 **41.94 GB**，建议给输出预留 **45 GB** 可用空间；如果 XCI 同时保存在本机，还需计入约 **42.72 GB** 的源文件空间。

取消会保留已完成部分；重新选择同一 XCI 可以续导。空间不足、外置盘断开、校验失败或目标资源版本冲突时会显示错误，并保留源文件和已有资源。build13 的手动重试入口是“检测 App 根目录中的 XCI／密钥”，也可重新手动选择 XCI。

### 方式四：使用已有的已提取资源

已有本作完整资源的设备只需更新 IPA，无需重复拷入资源。

### 导入时闪退或停住（build14 起）

导入界面会显示当前进程内存和采样峰值；“累计写入 7 GB”是已处理的资源量，并不等于占用 7 GB 内存。导入过程中每五秒保存进度／读写量／内存到 PJDVM39 根目录 `PJDV-import-diagnostics.jsonl`。下一次重试会将上一轮日志保留为 `PJDV-import-diagnostics.previous.jsonl`，方便对照闪退点。两份日志仅保存在本机，不含密钥内容、游戏文件路径或个人存档。

若设备仍退出，请同时保留这两份小日志，以及“设置 → 隐私与安全性 → 分析与改进 → 分析数据”中对应时间的 `JetsamEvent` 或 PJDV 崩溃记录。仅凭设备总内存不能断定终止原因；M1／iPadOS 18 需要对应真机回测。不要为重试删除原 XCI 或个人存档。

## 开发候选 build 9：真实游戏插帧研究（2026-10-22）

这段记录描述 build9 的本地研究结果。build10 包含该研究链，但仍未成为已验收的画质预设，默认关闭。

## build10：Mac Big Sur 与 GPU 档位（2026-10-22）

- 最低芯片 M1／Apple GPU family 7；Mac Catalyst 部署目标 14.0、对应 macOS 11.0，退出辅助模块也为 macOS 11.0。第一代 M1 随 Big Sur 推出，见 [Apple 发布资料](https://www.apple.com/newsroom/2020/11/macos-big-sur-is-here/)。此处为兼容候选，不表示已在 Big Sur 真机验收。
- 特效资格由 GPU family 决定：family 7／8 默认 720p、最高 1080p，禁用 HDR、RT、120 FPS；family 9+ 保留高配选项，iPhone 仍限 1080p／60。系统升级不会把低配 GPU 变成高配档。
- API 可用性与硬件档位分开检查。旧系统使用标准 Metal 命令编码器、由 MTLArgumentEncoder 处理的资源句柄和经典 drawable 呈现；不调用系统不存在的 GPU 地址或显示链接口。MetalFX 弱链接，不可用时保留普通缩放；不存在的 API 不能仅靠 GPU family 开启。
- 游戏 RT 去除多余的系统 26 门槛，仍要求 family 9+、片元光追能力及实际使用的加速结构接口。HDR 测试不再因同类中的 MetalFX 插帧 API 而整体要求系统 26；MetalFX 帧插值自身仍须相应系统 API。
- 本轮通过：Mac、iOS 17 目标、模拟器 Release 构建；GPU 档位／分辨率回归；808 个常规游戏着色器的 MSL 2.3 编译与参数块布局检查。在当前 M3 Max 的独立测试存档中，强制 family 7 与 Big Sur API 路径，标题、菜单、《愛言葉》的三维人物和舞台可显示，低配菜单禁用 HDR／RT 并隐藏超出 1080p 的输出。
- 测试局限：强制路径不是 M1 或 Big Sur 的硬件／驱动模拟；旧系统实际启动、性能、显示呈现时间统计以及高配 Mac 的 HDR／RT 回归仍待验收。当前 Xcode 27 SDK 推荐 macOS 12 起，工程将范围诊断保留为警告；已检查输出主程序 Catalyst 最低版本 14.0、Info.plist 最低系统 11.0、辅助模块最低 11.0，未修改 SDK 或仅事后改写安装包版本号。
