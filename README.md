## 0.1.5 更新与验证范围

- **降低安装门槛**：iOS／iPadOS 最低 17.0，最低 GPU 为 Apple family 7（A14／M1 同代），iPhone 同样开放。iOS 使用标准 Metal 命令队列兼容提交路径；build10 的 Mac 最低目标已降为 M1／macOS Big Sur 11，实际旧系统验收尚未完成。
- **低配档（family 7／8）**：首次默认 720p、标准画质，最高输出 1080p；禁用 HDR、光追和 60→120。MetalFX Spatial 根据实际设备能力提供。低配的分辨率与画质单独保存，旧高配设置不能绕过输出限制。
- **30→60 模拟器实验**：iPhone 18 Pro／iOS 27.2 的独立合成场景通过中间帧读回、开关对照、切镜头、暂停恢复及重新进入检查。模拟器没有 MetalFX 框架，采用明确标注的替代算法；这不是实际游戏或苹果 MetalFX 插帧验收。独立插帧实验需要 iOS 26。真实游戏插帧研究链从 build9 起接入，但画质未通过验收，build10 普通启动同样不开放。

**本版为兼容性预览：** iOS、模拟器和 macOS 构建通过，family 7 限制档在 iPhone 18 Pro 模拟器可显示片头、标题和主菜单，720p／1080p 输出正常。**尚未在 iOS 17、M1／A14 真机验收**，也未验证 4 GB 内存设备的稳定性、全曲帧率和高配设备改走 Metal 3 后的 HDR／RT 回归。模拟器约 60 FPS 的菜单数据不代表旧设备性能。

## 本轮改进

- **场景与景深**：修复两条片元着色器的透明度控制流，以及 NVN 到 Metal 的深度范围转换。在已抽查的《39みゅーじっく！》镜头中恢复立方体表面、发光圆环、大屏内容和人物对焦；这不代表所有歌曲或光照已完全还原。
- **载入**：本体和 27 DLC 共用原生 FARC/gzip 解压路径；477,748 个压缩条目的内容核验通过。收益取决于歌曲资源组成，仍不能保证所有歌曲都瞬间载入。
- **独立渲染依赖**：精简包内附匹配的 Metal 着色器与反射缓存，资源导入后不依赖开发机的缓存目录。
- **iPhone 实验适配**：开放满足 Apple GPU family 7 的 A14 同代及更新设备（兼容性预览）；最高 1080p、60 FPS，隐藏 1440p、屏幕分辨率输出和 120 FPS 选项。手机布局与折叠姿态先在模拟器验证。
- **折叠布局**：展开居中显示，合上横屏，半折分为上部游戏和下部控制区；保留原比例，利用自然黑边放系统状态栏。折叠模拟器适配不等同于真实折叠设备验收。
- **摇杆编辑**：启动页可调整左右虚拟摇杆的大小与位置，按手机、平板及折叠姿态分别保存；折叠设备默认摇杆缩小。
- **语言对应**：选择日文、简体中文或繁体中文时，宿主界面与游戏使用同一语言。真机发现英文字符串表并不等于完整英文菜单：这份 JP 包会混用日文图片，因此暂不开放英文、韩文选项；旧设置选到这些语言时统一回退日文。少数底层诊断仍保留技术文本。
- **手柄图标**：新增按实体手柄类型选择游戏图标的路径，Xbox 的旋律预览顺序为 **Y、X、A、B（上、左、下、右）**；PS 复用原有符号素材，保留箭头模式和既有输入映射。M4 iPad 已用诊断指定 Xbox 图标验证主菜单/设置底栏、YXAB 预览和按键设定；本轮未连接 Xbox 实体手柄，热插拔识别与完整谱面仍待更多实测。部分预烘焙帮助图、标题 Press A 和中央手柄示意图仍显示原版标识。

## iPad 安装与首次启动

1. 给 IPA 使用你自己的有效开发签名，安装到受该签名允许的 iPad / iPhone。公开 IPA 未签名，不能靠把文件拷到 iPad 就完成安装。
2. 按系统要求启用 [开发者模式](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)。如系统要求信任开发签名，在“设置 → 通用 → VPN 与设备管理”处理对应开发者。
3. 打开 PJDV M39，使用下面的 XCI 导入或已提取资源方式。资源未就绪时“启动游戏”不可用。
4. 点击“启动游戏”，用虚拟 A、键盘 D 或实体手柄的确认键进入。A 可以跳过开头视频。

本地 development IPA 的签名只覆盖当前登记设备，并有有效期；换 iPad 需要重签。更新测试版尽量覆盖安装，先备份存档再做卸载操作。

### 方式一：直接导入 XCI

1. 在首页打开“导入 XCI／资源管理”。公开版先点“选择／更换 prod.keys”，选择本地密钥文件；本地内置密钥版可跳过这一步。
2. 点“导入 XCI”，选择同一 Title ID 的 MEGA39’s `.xci`。ZIP / 7z 需先解压；云端文件需先下载完整。
3. 保持 App 在前台，等待基础资源、所选更新合并及包内实际 DLC 导入完成，再点“完成 → 启动游戏”。

选择 XCI 只读取源文件并提取资源到目标目录，不把整份 XCI 移动或再复制到 App 目录。XCI 若在外置盘，输出资源写入 iPad 本机。空间按实际内容变化；已测 v1.0.9＋27 DLC 资源约 **41.94 GB**，建议给输出预留 **45 GB** 可用空间；若 XCI 也先拷到本机，则还要计入约 **42.72 GB** 的源文件空间。取消后再选同一 XCI 可以续导；断开外置盘、空间不足或校验失败会停止，原 XCI 与存档保留。

### 方式二：使用已有的已提取资源

已有本作完整资源的设备只需更新 IPA，无需重复拷入资源。

1. 准备已有的完整 GameResources 文件夹；历史 FullTest ZIP 也可作本地资源来源，不必重复提取。
2. 安装并至少打开一次 App。用线连接 iPad，在访达打开“iPad → 文件 → PJDV M39”，拷入完整的 `GameResources` 文件夹。
3. 等传输完全结束；打开 App 的资源管理，选择“使用已拷入本机的资源”。也可在“文件”App 中连接已准备好的整个资源目录。

必须保留准备完成的清单文件和文件夹结构，不要只拷贝 `rom` 子目录：

```text
PJDV M39 的 Documents/
└── GameResources/
    ├── game-content.json       # build10 新导入生成；历史 v1.0.9 目录可无此文件
    ├── romfs/                 # 也兼容 MEGA39-v1.0.9 这个目录名
    │   ├── preparation.json
    │   ├── complete.json
    │   ├── files.jsonl
    │   ├── rom/
    │   ├── rom_switch/
    │   ├── shader/
    │   └── ……
    └── DLC/
        ├── manifest.json
        ├── 1/
        ├── 2/
        └── ……                # 此为示例；数量以 manifest.json 为准，不要重新编号
```

也可以直接连接外置盘上已提取的目录；运行期间需一直连接。若希望使用本机存储的读取性能，先完整拷入本机。

## Mac 安装与导入

- 打开 DMG，把 PJDV M39 拖到可保留它的位置。完整资源版 App 约 42 GB；轻量版 App 需另行导入资源。
- 当前使用本地 ad hoc 签名，尚未 Apple 公证。首次打开按 [Apple 的未公证 App 说明](https://support.apple.com/102445) 检查并批准此 App。
- 轻量版：资源管理里先选择自己的 prod.keys，再选择 XCI，随后选择资源保存位置。可以选外置 SSD；导入完成后会记住位置。
- 已有完整资源：选择“连接已提取资源文件夹”，选同时含 `romfs` / `MEGA39-v1.0.9` 和 `DLC` 的父目录。
- 完整资源版在新设备上可以直接读取 App 内资源。使用外置盘目录时，运行期间保持该盘连接；路径失效后重新选择。

## 键盘映射

Mac 键盘、iPad Magic Keyboard / 外接键盘使用同一套固定映射，按物理 QWERTY 位置读取，目前不做改键面板。

| 键盘 | Switch 输入 |
| --- | --- |
| W | X（上面键） |
| A | Y（左面键） |
| D | A（右面键，确认） |
| S | B（下面键，返回） |
| 方向键 ↑ / ↓ / ← / → | 方向上 / 下 / 左 / 右 |
| I / K / J / L | 方向上 / 下 / 左 / 右 |
| Q / E | L / R |
| Space | X、Y、A、B 同时按下 / 松开 |
| Delete / Backspace（含 Forward Delete），或 P | ＋（暂停） |
| Enter / Return（含数字键盘 Enter），或 M | － |

**Return 不再兼任确认，确认使用 D。** ZL / ZR 暂不做键盘映射，两个摇杆也不提供键盘映射或编辑。支持长按和组合；失去焦点时清理按住状态。

## 手柄与触控测试

- DualSense：圆圈对应 Switch A / 确认，叉号对应 Switch B / 返回；方向键、摇杆、四个面键、L1 / R1 已经用户实测基本正常。
- 游戏震动用《Catch the Wave》测试成功的连续长滑键。EXTREME 开头约 1.7 秒、HARD 约 26.7 秒有可用于验证的长链；只敲普通短滑键不能验证这一路反馈。
- 震动为 GameController / CoreHaptics 的近似转换，尚非位精确的 Switch HD 震动。重连、左右反馈和延迟仍需更多回归。
- DS5 内置扬声器在 Mac / 移动设备上不受支持，游戏音频从设备或耳机输出，参见 [Sony 支持说明](https://www.playstation.com/en-us/support/hardware/pair-dualsense-controller-bluetooth/)。
- 虚拟手柄采用 Switch 布局，当前缩放 200%；有实体手柄时自动隐藏，也可手动开启 / 关闭。
- 主菜单请用方向和确认键；原版菜单文字不是全部都能直接点按。原作 Touch Play 和虚拟按键触控分别验收。

## 建议的测试顺序

1. 冷启动、跳过片头、进入选曲；抽查 EXTREME / EX EXTREME 和服装直接装备，确认原成绩保留。
2. 用《Catch the Wave》检查输入与长链震动；再测暂停 / 恢复、重试、回选曲和手柄断开重连。
3. 用《ゴーストルール》检查持续负载，比较普通放大与 MetalFX，记录画质、卡顿、帧时间、音画同步和温度。
4. 使用“退出游戏”确认保存后，重新启动检查黑屏、残音、闪退和存档。

M4 iPad 早前已完成《ゴーストルール》1080p 三轮、1440p 多轮，正常演奏采样约 60 FPS，但存在少量长间隔与载入停顿。不能据此声称所有歌曲和设备稳定真实 60 FPS。帧率浮窗不能替代长时间帧间隔、温度和音画同步验收。

## 验证范围与已知问题

- 原生 XCI 解密器已对这份 XCI 的全部 **41,943,373,493 bytes** 文件数据完成 IVFC 校验，并逐文件与此前 Python 提取 SHA-256 对照一致；28 个分区的目录指纹、数量和字节总量一致。

## 开发候选 build 9：真实游戏插帧研究（2026-10-22）

这段记录描述 build9 的本地研究结果。build10 包含该研究链，但仍未成为已验收的画质预设，默认关闭。

- 已将真实 NVN 游戏最终颜色帧接到 30→60 显示链；源游戏提交约 30 FPS，生成中间帧与真实帧交替显示约 60 FPS。Mac M3 Max 上已观察到两类帧的实际呈现回调。
- 候选采用双向图像块匹配和运动补偿，**不是 MetalFX 帧插值**。目前没有完整的原作运动向量、匹配深度、独立谱面/UI 输入。原有 MetalFX Spatial 超分功能保持独立。
- 已处理源贴图快照、跨 Metal 4／传统队列的完成依赖、暂停/后台历史重置、切镜头回退和源帧/生成帧分开计数。试验限 SDR、720p／1080p；不提供真实游戏 60→120。
- 合成移动图形的中间帧误差比重复真实帧更低，切镜头直接使用当前帧；但《愛言葉》实时 3D PV 抓帧仍发现头发、轮廓和背景伪影，**真实游戏画质验收未通过**。
- 收紧边缘阈值的替代方案退化成重复当前帧，未作为“修复”保留。显示 60 FPS 不等于画面合格，也不等于真实游戏以 60 FPS 更新。
- 源帧降到 30 会改变游戏帧处理频率并增加显示延迟；歌曲时间、判定窗口、手柄/触控反馈仍需回归验证。暂不承诺降低整机功耗、所有设备稳定 60，或稳定支持打歌。
- 普通启动保持原生 60，省电插帧入口暂不可选。仅显式研究启动参数 `PJDV_GAME_FG=1` 可启用候选；这不是推荐的正常游玩设置。

可复核的原始帧、生成帧、编译日志及实验记录保存在外置开发卷 `Build/GameFG-20261021`。下一步需要可靠的游戏渲染运动/深度输入及谱面/UI 处理，然后重新完成画质、时序和能耗对照。


## Build10 内容识别与语言检测

- 基础包可以不带更新或 DLC；按内容元数据选择最高更新版本，DLC 按包内实际存在且校验完成的内容声明。残留目录不会被自动计为已安装 DLC。
- 元数据缺失时只接受可以唯一识别的内容；元数据缺件、同版本冲突、错误 Title ID、损坏校验块会拒绝导入。重命名的 NCA 使用 CNMT 内容 SHA-256 解析。
- 解锁仍修改原生存档的开放／持有位：只保留原游戏注册的歌曲记录，不合成谱面、曲目或成绩；服装和道具由当前资源数据库决定是否可见。保留一次原始存档备份。
- 可选语言由实际文字表及菜单图片／动画共同决定。仅有 `str_array.bin` 不算完整语言包。宿主 UI 与游戏语言一致；缺失语言回落日语，已有三种完整 JP 语言会正常显示。
- 内容格式参考：[hactool 的 NCA/PFS0 声明](https://github.com/SciresM/hactool/blob/master/nca.h)、[Atmosphere 的 CNMT 声明](https://github.com/Atmosphere-NX/Atmosphere/blob/master/libraries/libstratosphere/include/stratosphere/ncm/ncm_content_meta.hpp)。本项目独立实现格式读取，不把这些参考资料当作原游戏源代码。
- 格式与续导测试：`Tests/ImportVariants/build_fixtures.py` 生成小型合成 XCI；`ContentTests.swift` 检查基础包、更新优先级、任意 DLC 子集、新索引、语言完整性、取消恢复、跨版本覆盖拒绝及源文件保留。合成样本不含商业游戏素材，也不代表真实版本全曲回归。


## build10：Mac Big Sur 与 GPU 档位（2026-10-22）

- 最低芯片 M1／Apple GPU family 7；Mac Catalyst 部署目标 14.0、对应 macOS 11.0，退出辅助模块也为 macOS 11.0。第一代 M1 随 Big Sur 推出，见 [Apple 发布资料](https://www.apple.com/newsroom/2020/11/macos-big-sur-is-here/)。此处为兼容候选，不表示已在 Big Sur 真机验收。
- 特效资格由 GPU family 决定：family 7／8 默认 720p、最高 1080p，禁用 HDR、RT、120 FPS；family 9+ 保留高配选项，iPhone 仍限 1080p／60。系统升级不会把低配 GPU 变成高配档。
- API 可用性与硬件档位分开检查。旧系统使用标准 Metal 命令编码器、由 MTLArgumentEncoder 处理的资源句柄和经典 drawable 呈现；不调用系统不存在的 GPU 地址或显示链接口。MetalFX 弱链接，不可用时保留普通缩放；不存在的 API 不能仅靠 GPU family 开启。
- 游戏 RT 去除多余的系统 26 门槛，仍要求 family 9+、片元光追能力及实际使用的加速结构接口。HDR 测试不再因同类中的 MetalFX 插帧 API 而整体要求系统 26；MetalFX 帧插值自身仍须相应系统 API。
- 本轮通过：Mac、iOS 17 目标、模拟器 Release 构建；GPU 档位／分辨率回归；808 个常规游戏着色器的 MSL 2.3 编译与参数块布局检查。在当前 M3 Max 的独立测试存档中，强制 family 7 与 Big Sur API 路径，标题、菜单、《愛言葉》的三维人物和舞台可显示，低配菜单禁用 HDR／RT 并隐藏超出 1080p 的输出。
- 测试局限：强制路径不是 M1 或 Big Sur 的硬件／驱动模拟；旧系统实际启动、性能、显示呈现时间统计以及高配 Mac 的 HDR／RT 回归仍待验收。当前 Xcode 27 SDK 推荐 macOS 12 起，工程将范围诊断保留为警告；已检查输出主程序 Catalyst 最低版本 14.0、Info.plist 最低系统 11.0、辅助模块最低 11.0，未修改 SDK 或仅事后改写安装包版本号。
